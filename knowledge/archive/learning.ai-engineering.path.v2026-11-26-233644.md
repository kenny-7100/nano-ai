# 从资深软件开发到 AI 工程的实践路线

## 原始问题与摘要

有十年以上、以前端为主的软件开发经验，怎样通过训练 LLM 理解技术并积累求职竞争力？

这是针对当前学习背景的路线建议，不是招聘市场统计或就业保证。可先利用既有工程经验，补齐模型、数据、评估和 GPU 知识，再通过实践选择后训练或推理系统等深入方向。

## 路线与交付

1. **小模型预训练**：理解张量、next-token loss、attention、优化和自回归生成；交付可复现代码与对照实验。
2. **实际任务微调**：建立已有模型与提示词基线，再判断是否需要训练；交付独立评估与失败分析。
3. **推理服务**：测量质量、延迟、吞吐、显存和并发；交付可运行服务与性能报告。
4. **专题深入**：围绕一个具体问题研究新技术，明确单卡可以验证的范围。

项目路线及当前进度见 [学习路线](../../docs/roadmap.md)。组件类型到 TSX 生成只是候选任务，尚未确定。

## 可迁移的能力与需要补齐的能力

软件工程经验可以迁移到模块设计、调试、接口、可观测性和产品交付。需要新增的能力包括张量与自动微分、训练目标、数据划分、实验控制、模型评估，以及 GPU 内存与计算的关系。通用工程经验不能直接替代模型或分布式训练经验。

## 有说服力的作品证据

- 有清楚问题和公平基线，而不是只有技术名称。
- 有独立评估和失败案例，而不是只展示几个好样例。
- 有版本、配置和成本记录，别人能够复查。
- 能解释为什么有效、什么时候无效，以及结论的边界。

例如，比较“基础模型 → 改进提示词 → 微调模型”，在同一评估条件下记录成功率与资源成本。若微调没有改善，也应保留真实结果并分析原因。

## 复习自测

1. 你的现有工程经验能够帮助解决哪些 AI 系统问题？
2. 为什么采用某项前沿技术，本身不构成能力提升的证据？
3. 什么证据可以证明一次微调确实有效？
