## 阶段 0：最小工程与数据流

**问题：一段文本如何成为模型学习的输入和目标？**

建立 Python 工程、一个可运行入口和必要检查。用字符级或其他简单教学编码演示 token IDs、批次形状，以及右移一位的输入与标签；正式模型的 tokenizer 后续独立选择。

需要理解：张量的 batch / sequence / vocabulary 维度、next-token prediction、数据划分、训练 token 数与文本条数的区别。

验收：能打印一个小批次并逐项解释输入和正确答案；检查标签对齐；本地可运行。暂不租 GPU。

## 阶段 1：最小语言模型

**问题：预测概率如何变成 loss，再变成参数更新？**

从一个简单预测基线过渡到最小 causal Transformer。先实现前向、loss、反向和生成，再逐步理解 attention、残差与位置编码。现代组件在基础机制清楚后引入。

需要理解：logits 与概率、交叉熵、梯度、训练和评估模式、因果遮罩、自回归采样。

验收：模型能在极小数据上过拟合；遮罩不会泄漏未来信息；生成过程能解释；保存加载前后结果在合适容差内一致。

小数据过拟合只用于检查训练路径，不能据此宣称模型具备泛化能力。

## 阶段 2：可复现的小模型预训练

**问题：怎样在固定计算预算下获得可以验证的能力提升？**

先用很小的配置跑通真实语料，再视预算扩展至约 100M～150M 参数。在单张 32GB GPU 上测量吞吐、峰值显存与验证 loss；第一轮累计训练量可以从数亿 tokens 评估起，是否继续由结果和预算决定。

需要理解：tokenizer、语料质量、AdamW、学习率、有效 batch size、混合精度、梯度累积、checkpoint 恢复和过拟合。

验收：独立验证集、固定生成提示、两组有清楚问题的对照实验、一次恢复训练检查，以及真实的时间与成本记录。短跑估算与最终测量分别标注。

## 阶段 3：实际任务与参数高效微调

**问题：什么时候需要微调，如何证明它比已有方案更好？**

选择一个可评估任务和合适的 3B～8B 已有模型。候选任务是根据组件类型与需求生成 TSX；确定任务时再设计成功指标、数据划分与许可证检查。

先建立基础模型与提示词基线，再做 SFT / LoRA / QLoRA。基于任务需求决定是否加入检索。不要因为路线图列出某项技术就强行使用。

需要理解：chat template、loss masking、低秩适配、量化、训练数据质量、任务指标与测试泄漏。

验收：统一评估条件下的基线比较、失败案例分类、质量与资源开销的实际记录。没有提升也是需要解释的有效结果。

## 阶段 4：推理与服务

**问题：怎样把模型能力变成可测量、可使用的服务？**

部署 API，建立性能测量。前端可以作为实验查看与演示工具，在核心评估稳定后再加入。

需要理解：prefill / decode、KV cache、批处理、量化、首 token 延迟、输出 token 速度、吞吐与并发的区别。

验收：可运行的服务与调用样例、固定输入条件下的质量和性能报告，以及明确的资源与运行限制。

## 阶段 5：选择一个方向深入

根据前面的实践选择一个主题：偏好优化、可验证奖励、长上下文、蒸馏或推理优化等。先提出具体问题，再阅读论文与代码，并决定哪些实验在单卡上可验证。

验收：一份问题明确、对照合理、结果真实的专题报告。明确区分亲自测量、文献结论与尚未验证的推断。
